执行摘要

RSI 的核心主张：系统改进自身能力，且改进后的版本能把同一改进能力再次施加到自身，从而形成复利式增长。关键不在"自我改进"本身，而在——负责改进的那部分也被改进了。

这四篇论文勾画出 RSI 正在爬升的四层阶梯：L0 答案级（Reflexion, Best-of-N，已工业化）→ L1 代码级（DGM 改写 agent 代码）→ L2 权重级（SEAL 让模型给自己写训练数据）→ L3 策略/系统级（Terminal-RSI 让 agent 递归精炼自己的策略）。阶梯越高，agent 能修改的边界越广，但面临的约束也越硬——grounding（必须有外部验证信号）、collapse（自我训练会塌缩）、compute（每一轮都要花钱）。

选这四篇的原因：DGM 是 L1 的代表作，SWE-bench 20%→50% 是目前 RSI 方向最扎实的 benchmark 增益；SEAL 切换到 L2，把"自我改进"从"改代码"变成"改参数"，技术面完全不同；Terminal-RSI 是 2026.10 最新的 L3 系统，直接以 RSI 命名，用 TB-GAE 解决了长轨迹 credit assignment 这个共同难题；Taxonomy Survey 是坐标系——它不是另一个 RSI 系统，而是把 1250 篇文献分成"改进对象 × 闭环程度"的双轴，并首次系统讨论了 RSI 的三重约束。

读完这四篇，你应该能回答三个问题：① RSI 到底是什么（不是什么）；② 为什么它能工作（以及什么时候不能）；③ 下一步往哪里爬（爬之前要先解决什么）。

框架 · RSI 的四层阶梯

本报告用一个四层阶梯来定位所有 RSI 工作。每一层的"改进对象"不同，技术面和约束也不同。四篇精选覆盖了从 L1 到 L3 的爬升，外加一篇 taxonomy 负责把整张地图拍平。

阶梯越高，agent 能修改的边界越广。但能力上限的提升与三重约束（grounding / collapse / compute）的刚性几乎同步增长。L0 已工业化但受限于基座模型；L1 代码级最成熟（DGM）；L2 权重级突破基座但易灾难遗忘；L3 系统级最有想象力但评测最难。
① · L1

Darwin Gödel Machine

2025.5 · arXiv:2505.22954 · ICLR 2026 · Jenny Zhang, Shengran Hu, Jeff Clune
一句话主张
THE CORE CLAIM

让 agent 反复改写自己的代码（提示、工具、上下文管理、peer-review 机制……），用真实 benchmark 验证，成功者入 archive 并继续演化——这样的开放式演化能让 agent 自己发现"什么才是好的 agent 架构"，而不只是"怎样解某个具体问题"。

技术机制拆解

DGM 的设计有五个关键部件，每个都对应一个工程决策：

① Archive
持久代码仓库
存放已验证的 agent 变体，新变体从此采样
② Sampling + Mutation
LLM 驱动补丁
从 archive 采样一个变体，让 foundation model 产生新的"补丁"
③ 开放探索
多样化搜索
不同变体走不同演化路径，形成 agent 多样性树
④ 实测验证
代码执行
不做理论证明，用 SWE-bench / Polyglot 实测
演化循环（极简伪代码） archive = [初始 agent A0] while 预算未耗尽: parent = sample_agent(archive) patch = foundation_model.generate_patch(parent, task) child = apply(parent, patch) if pass_sandbox(child) and verify(child): # ← 关键：两个验证门 archive.add(child) report(archive.best_score)
关键设计取舍：不做 Gödel Machine 要求的"数学证明"，换成"benchmark 实测"。这是整个方向的哲学转向——接受启发式验证，换取可扩展性。

实验成果

DGM 在两个 coding benchmark 上的自增益是目前 RSI 方向最扎实的 benchmark 数字。

  • SWE-bench Verified：20.0%（起点）→ 50.0%（终点），2.5× 相对提升
  • Polyglot：14.2%（起点）→ 30.7%（终点），2.16× 相对提升

更重要的是：DGM 自发现的 agent 架构改进包括更好的代码编辑工具、长上下文窗口管理、peer-review 机制——这些都不是人工预设的"正确方向"，而是演化过程自然产生的。

局限性

① 没有解释性：为什么某个补丁起作用？DGM 不回答，只知道"benchmark 分数高了"。这在安全议题上是明显的短板。
② 受基座模型能力硬约束：archive 里的所有变体都由同一个 foundation model 生成，演化天花板就是基座的代码修改能力。
③ 成本未公开：每一轮演化要跑 SWE-bench 实测，需要的 GPU 小时数论文没说——这在工业落地时是个硬伤。
④ Open-ended vs 有界：DGM 声称"开放式探索"，但 archive 大小、补丁长度、评估预算都是有界的，严格来说仍属于有界自我精炼向开放式 RSI 过渡的中间态。

与脉络的关系

DGM 在 L0→L2 之间起了承上启下的作用：它把 RSI 从"改答案"推进到"改 agent 自身代码"，比 Reflexion / Best-of-N 跨了一步，但还没碰到模型权重（那是 SEAL 的事情）。随后的 Huxley-Gödel Machine（2510.21614）用 metaproductivity 估计血脉潜力进一步超过 DGM；HyperAgents（2603.19461）指出 DGM 的演化指令仍由固定机制产生，把"产生改进指令"也纳入被优化范围。DGM 相当于 L1 的 "alpha"，后续工作都以它为基线。

② · L2

SEAL · Self-Adapting Language Models

2025.6 · arXiv:2506.10943 · NeurIPS 2025 · Zweiger, Pari, Kim, Agrawal (MIT)
一句话主张
THE CORE CLAIM

让 LLM 自己生成 self-edit——一段指令，可能重组信息、指定训练超参、调用工具做数据增强——再用 SFT 把这段 self-edit 变成持久权重更新。这样自我改进就不再停留在上下文窗口，而写进了参数本身。

为什么是 L2 而不是 L1？

DGM 改的是 agent 代码（prompt、工具、peer-review 机制），这些代码由一个外部 foundation model 写出来，agent 自身的模型权重是固定的。SEAL 改的是 agent 的模型权重——self-edit 是同一模型生成的，然后通过 RL + SFT 变成权重更新。这意味着：

L1 → L2 的核心跃迁
改进对象从"agent 的代码"（可以被外部人读、理解、审核）变成"模型的权重"（不可解释的参数向量）。好处是真正突破了基座能力上限；坏处是引入了灾难遗忘、分布塌缩等 L1 不会遇到的风险。
训练闭环（简化版）
输入 → 模型生成 self-edit → 执行 self-edit（数据增强/超参指定）→ SFT 更新权重 → RL 奖励"更新后的下游表现"→ 学会生成更好的 self-edit
Self-edit 可以是什么 A. 重组信息：把同领域分散的知识碎片重新编织成训练样本 B. 指定优化超参：为某类任务推荐更合适的学习率 / batch size C. 调用工具做数据增强：主动合成 hard example、对比样本、推理轨迹 D. 决定"要不要做 self-edit"：有些任务本来就不需要改编，模型学会了识别这种情况

实验成果

任务方法指标提升
知识注入（QA）SEAL vs 普通 RAG准确率显著更高，且新能力是持久的
Few-shot 泛化SEAL vs 固定 prompt adaptation跨域任务准确率基线 62% → SEAL 71%
灾难遗忘测试连续三次 self-edit 后测原始任务原始任务准确率仍有显著下降——L2 的核心代价

局限性（坦白讲）

① 灾难遗忘是硬伤：论文自己测到——连续做 self-edit 后，模型在原始任务上的表现显著下降。这是"让模型自己写训练数据"的内生问题，目前没有完美解法。
② self-edit 的形式还很窄：目前只能做重组 / 超参 / 数据增强三类改动，还不能做"改注意力机制"或"改层数"这种架构级修改。
③ RL 奖励仍然不可靠：奖励信号是"下游任务表现"——如果下游指标本身有漏洞，self-edit 就会被误导（这正是 SEIS 在推理引擎上观察到的 reward hacking）。
④ 与 L1 系统不互斥：SEAL 没有 agent 级的代码自我改写；DGM 没有模型级的权重自编辑。两者是互补而非替代关系。

与脉络的关系

SEAL 的出现让 RSI 从"改代码"升级到"改参数"——这是技术面上的真正跃迁。随后的 Absolute Zero（2505.03335）和 R-Zero（2508.05004）把这个方向推到极致：零外部数据、模型自己出题自己求解、形成自博弈课程。但它们也因此最受 三重约束 的钳制——grounding 最弱（没人给验证信号）、collapse 风险最高（自博弈容易走向分布塌缩）。

③ · L3

Terminal-RSI

2026.10 · arXiv:2610.22192 · Yang, Li, Shi et al. (清华 + 商汤 + 清华叉院)
一句话主张
THE CORE CLAIM

在 terminal agent（需要多步工具调用来完成代码任务）上，交替执行递归自改写（Recursive Self-Rewrite，RSR）和递归策略精炼（Recursive Policy-Refine，RPR）——前者把已验证的轨迹改写成更好的训练样本，后者继承 critic 继续精炼策略。关键是 TB-GAE：在 agent 与环境的多轮交互间保留 token 级 baseline 同时做轮次间衰减，解决长轨迹 credit assignment。

为什么是 L3？它比 SEAL 多了什么？

SEAL 改的是"处理单个输入的模型权重"；Terminal-RSI 改的是"agent 与环境交互的整个策略"——包括何时调用工具、如何处理 tool 输出、如何做跨多轮的计划修订。这是从"模型适配"到"agent 策略学习"的质变。它直接以 RSI 命名，因为整个训练过程就是一个递归改进闭环。

五个技术贡献（论文自称）

① RSR
Recursive Self-Rewrite
把已验证轨迹改写成更好的训练样本
② RPR
Policy-Refine
继承 critic，精炼 policy
③ TB-GAE
Turn-Boundary Skip-Obs GAE
跨交互轮次的 credit assignment
④ FDR + SPR
Reward 校准
Family Dense + Success-Prioritized
Qwen3.8-27B base→ RSR-1→ RPR-1→ RSR-2→ RPR-2→ Terminal-RSI-27B
两阶段交替递归：RSR 做轨迹改写（属于 RSI 的"改进执行者"环节），RPR 做策略精炼（属于 RSI 的"改进策略"环节），critic 在各阶段间 handoff 确保知识不丢。

实验成果（核心数字）

从 base Qwen3.8-27B 到 Terminal-RSI-27B，五个阶段在 Terminal-Bench 4.0 上从 4.5% → 19.84%。

其他值得注意的数字：

  • Terminal-Bench 2.1：86.52%（较高起点，收益相对收敛）
  • Terminal-Bench Hard：79.00%
  • LHTB：process reward 从 0.21 → 0.37，strict completion 从 0/46 → 5/46
  • SWR100：success 从 3.00% → 6.00%（翻倍）

我觉得最值得注意的两个点

TB-GAE 是真正的工程贡献
"跨交互轮次的 credit assignment"是所有 L3 RSI 系统共同面对的难题——agent 跑 30 轮工具调用后，到底哪一轮导致了最终成功？TB-GAE 的做法：保留 token 级 baseline 但在轮次边界做衰减。这不是首次提出类似想法，但 Terminal-RSI 把它在 RSI 训练中做实了。
成本没说
27B 模型 + 五阶段训练 + 每个阶段都要跑 Terminal-Bench，GPU 小时数必然巨大。论文没有披露预算。这是 L3 所有系统的共同问题：compute 约束在 L3 上变得最刚性。

局限性

① Terminal-Bench 是 terminal agent 专用基准。这意味着 Terminal-RSI 的 RSI 能力是否能 transfer 到其他 agent 场景（科研、写作、分析）还不清楚。
② 两阶段交替是手工设计的。RSR 和 RPR 何时切换、每个阶段多少轮、学习率如何调度——这些都是人写的 curriculum。按照 HyperAgents（2603.19461）的标准，这说明 Terminal-RSI 的"改进指令"本身还不是自生成的。
③ 验证器能力 = 改进上限。Terminal-RSI 的所有收益都来自 verifier 的反馈质量。如果 verifier 本身有漏洞，就会被 reward hacking——和 SEIS 发现的问题完全一样。

RSI Taxonomy · Bounded vs Open-Ended

2026.7 · arXiv:2607.07663 · Chen, Wang, Qu · 1,250 篇文献覆盖
一句话主张
THE CORE CLAIM

"self-refine / self-reward / self-play / self-evolve" 这些词被混用到了本质不同的抱负上。把它们按改进对象 × 闭环程度两条轴拆开：有界自我精炼（bounded self-refinement）是收敛、可评估、已工业化的那条；开放式 RSI（open-ended RSI）在 grounding / collapse / compute 三个维度上都还受硬约束。这是第一篇系统性讨论 RSI 边界条件的文献。

核心分类框架

轴 1：改进对象（What）

  • 行为：同问题下反复打磨答案（Reflexion、Best-of-N）
  • 策略 / 权重：让模型的参数本身改变（SEAL、Absolute Zero、Terminal-RSI）
  • 评估器：让 verifier / judge 自己演化
  • 研究过程：让 agent 决定"下一个该探索什么"（RSI-Master、AREX）

轴 2：闭环程度（How）

  • human-in-the-loop → semi-closed → fully closed
  • 论文观察：越靠 fully closed，self-evaluation 就变得越关键——但它也最脆弱
本报告四篇论文在 taxonomy 双轴上的位置。注意 DGM 虽然是 L1 但仍有半闭环节点（archive 的扩展需要人工写初始 agent）；Terminal-RSI 离 fully closed 最近但 curriculum 仍是手工的；"人类写 RSI taxonomy"本身是 human-in-the-loop 的极端例子。

最有价值的三个洞察

① 验证器层级（Verification Hierarchy）
把信号按可靠性排序：formal verifiers（最强，如 SWE-bench 执行检查）→ process reward models → self-consistency → intrinsic self-assessment（最弱，容易 self-confirming loop）。已展示的自我改进强度与这条层级正相关。这是最重要的一个观察——解释了为什么 DGM 用 SWE-bench 就能拿到硬增益，而 self-assessment 系统容易 reward hacking。
② 失败模式有系统结构
self-confirming loops（模型只见过自己生成的数据，逐渐丧失泛化）、model collapse（RL 训练导致分布塌缩）、diversity collapse（演化过程逐渐收敛到相似解）——这些不是工程 bug，是闭环系统的内生风险。DGM 用 open-ended exploration 对抗 diversity collapse，但也引入了代价。
③ "研究方向设置"是独立瓶颈
论文把人类留在循环中的原因拆成两部分：verification problem（验证器层级可以帮你量化这个瓶颈）和一个prior problem（选择"什么值得被改进"本身——verification hierarchy 完全不覆盖）。这是让 RSI 真正落地时最被忽略的方向。

RSI 的三重约束

Taxonomy Survey 提出的 grounding / collapse / compute 三条约束是所有 RSI 系统的硬天花板。下图把四个对象放在同一个雷达上，直观看出它们各自的主要压力：

越往外压力越大。"有界自我精炼"几乎不暴露约束（已工业化）；DGM 压力中等但有硬 benchmark 托底；SEAL collapse 风险最高；Terminal-RSI compute 开销巨贵。

如何解读这三条约束

① Grounding（必须有外部验证信号）
RSI 系统的改进循环的价值完全依赖于有一个"什么是更好"的信号。如果验证器弱（self-assessment），就会 self-confirming loop；如果验证器强（formal verifier），但它本身有漏洞，也会 reward hacking。提升空间：让 verifier 也能自我改进——但这立刻遇到"谁来验证 verifier 的改进"的循环论证。
② Collapse（自我训练会塌缩）
模型自己出题自己做，很容易逐渐收敛到自己熟悉的那个方向，丧失多样性。SEAL 的灾难遗忘、Absolute Zero 的分布塌缩、DGM 可能的 diversity collapse 都是这个家族的不同症状。提升空间：显式的 diversity 保持（DGM 的 open-ended exploration）、课程设计、偶尔引入外部数据。
③ Compute（每一轮都花钱）
L3 系统最贵：Terminal-RSI 27B 模型跑五阶段训练 + 每阶段都要在 Terminal-Bench 上实测。Taxonomy Survey 计算：每一轮 RSI 的成本是上一轮的 3–10×，因为你需要跑完整训练才能知道改进有没有用。提升空间：样本效率更高的 verifier、curriculum 更聪明（让 RSI 不会在注定失败的方向上浪费算力）、distill 把学到的改进压缩回小模型。

学习建议 · 怎么读这四篇

推荐的阅读顺序

  1. 先读 Taxonomy Survey（44 页），建立坐标系。它让你知道 DGM/SEAL/Terminal-RSI 各自落在哪里、为什么那个位置重要。如果上来就读 DGM，你容易以为"RSI 就是改写代码"，但 SEAL 和 Terminal-RSI 告诉你不是。
  2. 再读 DGM，因为它有最硬的 benchmark 数字。重点读 archive 设计和 sandbox + verify 两个验证门。它的失败（cost 未披露、解释性缺失）也很有教育意义。
  3. 然后读 Terminal-RSI，因为它最新、最技术密集。TB-GAE 和 RSR/RPR 交替是 L3 最值得挖的技术细节。读的时候留意它的 curriculum 还是手工设计的——HyperAgents（2603.19461）下一步就是让这个也被 RSI 化。
  4. 最后读 SEAL，因为它换了技术面。重点读 self-edit 的定义和 RL 奖励设计。它的灾难遗忘问题是所有想做 L2 的人都要提前想清楚的。

如果只挑两篇精读

想懂"R 指的是什么"→ DGM + Taxonomy
DGM 把"递归"变成了你能看到的演化树（archive + open-ended）；Taxonomy 把"I"（self-improvement）拆成了四个不同对象，让你不再混淆"self-play / self-reward / self-evolve"。这两篇读完你就不会再对 RSI 是什么感到模糊。
想懂"下一步怎么爬"→ Terminal-RSI + Taxonomy
Terminal-RSI 是当前离 fully closed 最近的系统，TB-GAE 是解决长轨迹 credit assignment 的真实工程贡献；Taxonomy 把 Terminal-RSI 的 curriculum 手工性放进"谁来设研究方向"这个更大的问题里，告诉你下一步的真正瓶颈在哪。

三条研究方向上的空位

① curriculum 自生成
DGM / Terminal-RSI / HyperAgents 的改进指令、演化路径、训练阶段还是人写的。让 RSI 自己设计 curriculum——这是从"人工 RSI"到"真正 RSI"的下一步。
② verifier 自我改进
Taxonomy 把 verifier 作为轴之一，但目前没有系统让 verifier 本身进入 RSI 循环。grounding 约束在 verifier 弱时最紧——让 verifier 自己变强可能是突破 grounding 约束的办法。
③ cost-aware RSI
所有论文都不提 cost，但 L3 系统必然巨贵。"改进收益 ÷ 改进成本"这个指标没人系统优化过——这是让 RSI 真正可用的工程关键。
